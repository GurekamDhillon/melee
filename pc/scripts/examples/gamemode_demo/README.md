# Two-area demo

An offline Final Destination experiment using the BF interior kit and the reusable
[Gamemode library](../../lib/gamemode.md). It runs in an existing match; no fixed campaign,
new native menu or fighter-spawn service is introduced.

1. Hall: one Goomba/ReDead wave. Clear both (defeated or removed), then enter the doorway on the right.
2. Gallery: two real Target Test targets and a three-second active-play timer. Break both
   and reach the right doorway to complete. Entry into each room creates a checkpoint.

The entry is `scripts/main.lua`, generated by concatenating `../../lib/gamemode.lua` and
`demo.lua`. Only the generated entry belongs in `scripts/`; loading separate library and
demo scripts would create separate sandboxes. Update/check it with:

```powershell
python pc/scripts/examples/gamemode_demo/bundle.py
python pc/scripts/examples/gamemode_demo/bundle.py --check
```

The mod needs four existing exported BF kit models plus their atlas/sidecars. No disc assets
or generated binary art are added here. Given the kit export's `models` directory, prepare
a mod folder (example destination inside this worktree):

```powershell
python pc/scripts/examples/gamemode_demo/bundle.py --kit-models "../../melee/pc/scripts/examples/bf_interior_room/models" --output "scratch/gamemode_demo"
```

The command validates the asset set before copying. If it is absent, use the existing
`pc/assets_src/bf_interior/export_kit.py` workflow first; that Blender asset export was not
run for this task. Install the resulting folder as `mods/gamemode_demo` beside the game.
Enable only this demo when testing its camera/room ownership. The stock stage remains under
the room; other fighters and the original match rules are unchanged.

Console commands: `gm_status`, `gm_retry`, `gm_stop`. Retry requires a live P1. Save/load
through ordinary quick slots; loading restores the current room, wave and phase. Rewind
is explicitly refused because it would skip the Lua director. Missing assets/capacity or
invalid relocation produces an error HUD/log, not a cleared encounter. The source hash
guard rejects mode-bearing states after script edits; keep the source fixed during tests.

See [gamemode-report.md](../../../../gamemode-report.md) for the exact Windows lane and
validation status. Visual composition, collision, enemy portability and boss integration
have not been tested in the game for this task.

The two-area PASS/FAIL integration test lives in `pc/tests/gamemode_demo.lua`. Append it
to the real demo in the same sandbox so it can inspect the director without changing it:

```powershell
python pc/scripts/examples/gamemode_demo/bundle.py --test pc/tests/gamemode_demo.lua --output scratch/gamemode_demo_test --kit-models "PATH/TO/KIT/models"
```

Install that mod instead of the ordinary demo, start offline VS on FD with Fox P1,
an idle human P2 and time=0. It attacks the hall enemies, verifies terminal events/reasons,
enters the gallery, breaks both targets, waits for the survival goal and takes the exit.
It logs `GMD PASS`/`GMD FAIL` and calls `gd.quit()` on success, failure or deadline.
This is a mod integration test, not a standalone pad script. It was not run for this fix.
