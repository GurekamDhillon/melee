# mod-c-v1: one C mod source, native and WebAssembly

Spec version: mod-c-v1, ABI 1.0, hook table `hooks-v1`, document revision 2026-11-02. Shared by melee-unlocked (native C/C++
source port of the decomp) and this repository (native Rust port plus the C build). Everything below is derived from our
source: the decomp under `src/`, `rust/melee_types` (field names and offsets), `rust/melee_link` (the link table),
`config/GALE01/symbols.txt` (retail addresses). No disc-derived data is used or stored.

Files: `docs/specs/mod-c-v1.md` (this), `docs/specs/gdmod.h` (the declarations), `docs/specs/hooks-v1.tsv` (generated by
`tools/specs/gen_hook_table.py`; `--check` detects staleness), `docs/specs/examples/hello_mod.c`.
Related: `docs/specs/nhv1.md` (the digest used for verification, section 9).

## 1. Goals and non-goals

| goals | non-goals |
|---|---|
| One plain-C source compiles unchanged to a native object (host build) and to `wasm32` (our build) | No scripting language or interpreter running inside the frame |
| Zero added latency natively: a hook is a direct call (or static inline), one array per hooked address, nothing for an unhooked address | No dynamic loading of untrusted native code (native mods are compiled in by the host builder; the sandbox is the wasm side) |
| Bit-identical gameplay between the two builds for the same mod and inputs | No access to arbitrary game memory, raw struct pointers, or calling arbitrary game functions (v1 is accessors only) |
| Rollback-correct with no save/load code in the mod | No rendering, audio, file, network, clock, thread, or host-RNG access |
| Hook points stable across decomp renames and across both ports | No mod-defined new characters, stages or assets (m-ex territory) |
| Wasm is AOT-compiled (cranelift/wasm2c class), never interpreted per frame | No DoS protection in v1 (a looping mod hangs the frame; OPEN 9) |

## 2. Execution model

| rule | detail |
|---|---|
| when mod code runs | only inside a hook, called by the host at a decomp function boundary, on the game thread, at a fixed point of the logic frame. Never between frames, never on the render path |
| mod entry points | hook functions only, plus the exported data `gd_mod_manifest` and `gdmod_abi_version`. There is no `init`, `update` or `shutdown`; first-use state is the zero-initialised globals |
| wasm | one instance per mod, AOT, memory fixed at `min = max`, no `memory.grow`, no table growth, no threads, no SIMD, no start function. Imports: module `gd`, only the functions of `gdmod.h`. Any other import refuses the load. Function pointers in the manifest are indices into the exported function table (`--export-dynamic` exports it) |
| native | the mod is a translation unit of the host build, or a DLL/SO loaded at host startup. The `GD_API` functions are either static inline in a host-supplied header or ordinary externs |
| calls into the game | none in v1. Accessor writes are plain stores, never invoke hooks, never call game callbacks. `gd_fighter_request_action_state` is queued and applied by the host after the hook chain returns |

## 3. Hooks

### 3.1 Identity

A hook is keyed by the RETAIL GameCube function address (GALE01 1.02, the `.text` address in `symbols.txt`). The address is
the only identity a mod depends on. Each row of `hooks-v1.tsv` also carries a stable `name` and the current decomp symbol as
`alias`; both are for humans and tooling. Upstream may rename `alias` at any time; the address and the meaning of a row never change
within `hooks-vN`, and rows are append-only.

| tsv column | meaning |
|---|---|
| `name` | stable mod-facing id, dotted (`damage.fighter_take_damage`, `action.Wait.anim`) |
| `address` | retail address, the key |
| `signature` | ABI signature `ret(arg,...)`; types `void i32 u32 f32 gd_fighter gd_item gd_gobj gd_spawn gd_ptr`. A `gd_ptr` argument is always 0 in v1 |
| `phase` | the family, table 3.2 |
| `alias` | decomp symbol at generation time |
| `site` | how an implementation intercepts it: `call` (a direct call from other code; a seam in a link table), `proc` (registered by `HSD_GObj_SetupProc`, dispatched by `HSD_GObj_RunProcs`), `state` (a function pointer in a `MotionState` table), `scene` (a pointer in the scene table, `gmscdata.c`) |
| `link` | `yes` if `alias` is a key of `rust/melee_link/linked_keys.txt` (our cross-TU seam exists); `no` = the Rust port needs a new seam or wraps the proc/table entry. Informational for implementers |
| `sig_src` | `decomp` = prototype found in `src/`; `assumed` = family default, and then only void pre/post hooks are allowed on that row (none in v1) |

### 3.2 The v1 subset: 882 rows

| phase | rows | what | decomp entries |
|---|---|---|---|
| `frame` | 1 | the logic iteration boundary; `frame.begin` = pre of this row, `frame.end` = post of it | `HSD_GObj_RunProcs` 0x80390CFC, called once per iteration from `gm_801A4D34` |
| `match.start` | 2 | scene enter (Vs, Training) | `gm_Scene_Vs_OnEnter`, `gm_Scene_Training_OnEnter` |
| `match.end` | 1 | scene exit (Vs) | `gm_Scene_Vs_OnExit` |
| `stage.update` | 4 | stage per-frame proc, map collision update, stage load, stage start | `Ground_801C0C2C`, `Ground_UpdateMapColl`, `Ground_OnLoad`, `Ground_801C0FB8` |
| `fighter.life` | 2 | fighter create, fighter death processing | `Fighter_Create`, `Fighter_UnkProcessDeath_80068354` |
| `fighter.proc` | 14 | the fighter GObj procs in `HSD_GObj_SetupProc` priority order (`fighter.procNN`, NN = priority in hex; 0E is the `hit` row) | `Fighter_8006A1BC` to `Fighter_8006DA4C`, incl. `Fighter_procUpdate` (04), `Fighter_procMap` (06) |
| `hit` | 1 | per-fighter hit processing (priority 0E proc) | `Fighter_ProcessHit_8006D1EC` |
| `damage` | 3 | damage applied to a fighter (two entry points, the second wraps the first) and to an item | `Fighter_TakeDamage_8006CC7C`, `Fighter_UnkTakeDamage_8006CC30`, `Item_80269CA0` |
| `item.spawn` | 4 | item spawn core and its wrappers | `Item_8026862C`, `Item_80268B18`, `Item_80268B5C`, `Item_80268B9C` |
| `item.update` | 4 | item procs (priority 0 and 5), state change, destroy | `Item_802693E4`, `Item_80269978`, `Item_80268E5C`, `Item_802680CC` |
| `action.enter` | 19 | `ftCo_*_Enter` functions (common action-state entry) | generated from `ftCo_<State>_Enter` |
| `action.anim` / `.iasa` / `.phys` / `.coll` | 216 / 201 / 201 / 209 | per-state callbacks of the common (`ftCo_`) action states | generated from `ftCo_<State>_{Anim,IASA,Phys,Coll}` |

Character-specific states (`ftMr_`, `ftFx_`, ...), item kinds and stage-specific procs (`stageGObjN_GObjProc`) are not in v1; they
join in hooks-v2 by the same generator pattern. The generator fails if a curated symbol disappears from `symbols.txt`.
A mod that hooks both `damage.fighter_take_damage_wrap` and `damage.fighter_take_damage` sees one damage twice (the wrapper calls the other).

### 3.3 Semantics

| mode | signature | runs | return rules |
|---|---|---|---|
| pre | `gd_i32 h(args)` returns `GD_CONTINUE` or `GD_SKIP` | before the original, ascending priority | `GD_SKIP` omits the original and every later pre and the replace hook. For a non-void function the skipping hook sets the result with `gd_set_return_i32/f32` (last skipper wins; unset = 0) |
| replace | `R h(args)` | instead of the original; at most one per address across all loaded mods (a second is a load refusal) | the returned value is the function's result. May call the original once with the unmodified arguments via `gd_orig_call_void/i32/f32()` |
| post | void function: `void h(args)`. Non-void: `R h(args, R ret)` | after the original (or after replace or skip), descending priority (onion order) | non-void post returns the value to pass on; the final value is the caller's result. The args are the originals as passed |

| topic | rule |
|---|---|
| ordering between mods | per address and mode: ascending `priority` (int, -1000..1000, default 0), ties broken by `mod_id` bytewise ascending, then declaration order within the mod. Post runs in the exact reverse of pre order |
| load-order independence | the order above is a total order on (priority, mod_id, index); the order mods were passed to the loader must not change results |
| re-entrancy: game | the original may recursively reach the same address. Each activation runs its own pre/replace/post chain. Depth limit 8 per address; deeper activations run the original only and the host counts it |
| re-entrancy: mod | no accessor invokes a hook (section 2), so a hook cannot re-enter itself or another hook of the same mod |
| nested original | `gd_orig_call_*` inside replace does not re-run that replace or its pre hooks; hooks of other addresses fire normally |
| `frame` | pre = frame begin (all procs of this iteration still to run); post = frame end (all fighter, item, stage and camera procs ran). Post hooks run BEFORE the NHV1 sample (section 9), so mod effects are in the digest (OPEN 3) |
| `proc` and `state` sites | the host wraps the registered function pointer; a hook on `fighter.proc04` fires once per fighter per frame, argument = that fighter's handle |
| arguments | handles are per call; stale or foreign handles read 0 and write nothing (counted by the host, not an error) |
| cost | the loader resolves pre/replace/post lists once into a per-address array; an address with no hook is called exactly as before. With no mod loaded the loader installs nothing |

## 4. Handles and accessors

WebAssembly cannot dereference host memory, so a mod never holds a struct pointer. It holds handles and calls accessors, or copies a
struct slice in or out. Natively the accessors may be `static inline` (define `GD_ACCESSORS_INLINE=1` and
`GD_HOST_INLINE_HEADER`, see `gdmod.h`), so a native read is a load of the same field the wasm host reads.

| handle | wraps | notes |
|---|---|---|
| `gd_fighter` | `Fighter` + its GObj | `gd_fighter_from_slot(0..3)`; sub-fighters (Nana) not addressable in v1 |
| `gd_item` | `Item` + its GObj | `gd_item_count` / `gd_item_at` iterate in item-list order |
| `gd_gobj` | any `HSD_GObj` | only `gd_gobj_kind`, `gd_gobj_to_fighter`, `gd_gobj_to_item` |
| `gd_player` | player slot | reserved; v1 uses slot numbers (`gd_player_*`) |
| `gd_stage` | the stage | reserved; v1 exposes `gd_stage_kind` |
| `gd_spawn` | `SpawnItem` request | valid only inside `item.spawn*` hooks; setters in pre only |

Encoding: `u32`, `(generation << 16) + index`, 0 invalid. Handle values differ between builds and must not be compared, hashed or kept
in mod state (section 6).

| accessor | decomp field (`rust/melee_types/src/gen.rs`) | offset |
|---|---|---|
| `gd_fighter_get/set_pos` | `Fighter.cur_pos` (Vec3) | 0xB0 |
| `gd_fighter_get/set_vel` | `Fighter.self_vel` | 0x80 |
| view `kb_vel` | `Fighter.x8c_kb_vel` | 0x8C |
| `gd_fighter_get_action_state` | `Fighter.motion_id` | 0x10 |
| `gd_fighter_get/set_percent` | `Fighter.dmg.x1830_percent` | 0x182C + 4 |
| `gd_fighter_get/set_facing` | `Fighter.facing_dir` | 0x2C |
| `gd_fighter_slot`, `_kind` | `Fighter.player_id` (u8), `Fighter.kind` | 0xC, 0x4 |
| `gd_fighter_get_input` | `Fighter.input`: slot 0 of `lstick`, `cstick`, `triggers`, `held_buttons`; `pressed_buttons`, `released_buttons` | 0x620 |
| `gd_item_read/write` | `Item.pos`, `x40_vel`, `facing_dir`, `kind`, `owner` | 0x4C, 0x40, 0x2C, 0x10, 0x518 |
| `gd_rand_u32(bound)`, `gd_rand_f32()` | `HSD_Randi`, `HSD_Randf` (0x80380580, 0x80380528) on the game seed (`HSD_RandSeedPtr`) | n/a |

Offsets document the implementation; the ABI is the function, not the offset. Bulk: `gd_fighter_read(h, &view)` fills a
`gd_fighter_view` (80 bytes) in one call; `gd_fighter_write(h, &view, mask)` writes only the fields named in `mask`
(`GD_FV_POS|VEL|KB_VEL|FACING|PERCENT`). Same for `gd_item_view` (52 bytes). View structs are 4-byte aligned, no padding,
little-endian, with `reserved` words that read as 0 and are ignored on write; sizes asserted in the header.

Value rules: the host NaN-canonicalises floats it hands to a mod and floats a mod writes (`0x7FC00000`).
`gd_fighter_set_facing` accepts only +1.0f and -1.0f. Accessors return values as of the call (a write in the same hook is visible to the next read).

## 5. Determinism rules

| area | rule | why |
|---|---|---|
| float contraction | `-ffp-contract=off` (clang/gcc) or `/fp:precise` with contraction off (MSVC); never `-ffast-math`, `-Ofast`; no FMA-enabling `-mfma`/`/arch:AVX2` without contraction off | FMA changes the last bit; wasm has no FMA, so the native build must not fuse |
| float model | x86-64 SSE2 scalar `f32` (no x87), round-to-nearest-even, `-fno-math-errno`. `double` allowed, libm not | identical IEEE results on both targets |
| NaN | wasm NaN payloads are nondeterministic. The host canonicalises at every boundary crossing; a mod must not branch on NaN payload bits or hash floats by bits; use `gd_isnan` | digests must agree |
| float to int | only `gd_f2i` (saturating, NaN to 0). A raw C cast is undefined out of range and wasm's `trunc` traps | a trap aborts the match |
| int | `-fwrapv`; divide and modulo only via `gd_div`/`gd_mod`; shifts below the width | div by zero traps in wasm and faults natively |
| libm | none. `gd_sinf gd_cosf gd_atan2f gd_powf` are host functions with ONE implementation for both builds. `gd_sqrtf`, `gd_fabsf` are exact IEEE inlines | libm results differ by platform |
| order | `gd_mul_add` is two roundings, `gd_dot3` is `(xx+yy)+zz`. Loops over fighters go slot 0..3, over items in `gd_item_at` order | float addition is not associative |
| time | no clock, timer, `rand()`, `time()`, thread, atomic, environment query. Only the logic frame (`gd_match_frame`) | |
| randomness | only `gd_rand_u32` / `gd_rand_f32`, which advance the game's RNG; those draws are game state and roll back with it | |
| uninitialised data | reading uninitialised locals or padding is forbidden; build with `-Wuninitialized -Werror` | differs between targets |
| layout | no dependence on pointer values, `sizeof` of host types, or game struct layout | |

## 6. State rule

| rule | detail |
|---|---|
| where state lives | only in the mod's file-scope globals and `static` locals with constant initialisers (`.data`, `.bss`). Nothing else survives a hook |
| no heap | no `malloc`, no `alloca` beyond 1 KiB, no VLAs. A fixed arena is allowed: a global `static gd_u8 arena[N]` managed by the mod |
| no pointers in state | state holds integers, floats and indices into the mod's own arrays. No data or function pointer in mutable state; no handle kept across frames (store slot numbers and re-resolve each hook) |
| no constructors | no dynamic initialisers, no `__attribute__((constructor))`, no thread-local |
| rollback | native: the host snapshots and restores the mod's `.data` + `.bss` as bytes. wasm: the host snapshots the instance's linear memory block (includes the stack region). Both are complete because nothing else holds state. The mod has no save or load code |
| snapshot timing | snapshots happen only between hook invocations, where the wasm shadow-stack global is at its initial value, so that one wasm global needs no capture |
| manifest size | `state_bytes` = `sizeof` of all mutable globals (author-measured). The host compares with the linked `.data+.bss` (native) or the declared memory (wasm) and refuses a mismatch beyond the stack |

| limit | v1 value |
|---|---|
| mutable state per mod (`.data` + `.bss`) | 256 KiB |
| wasm linear memory | 1 MiB, fixed (`--initial-memory=1048576 --max-memory=1048576`), stack 16 KiB (`-z stack-size=16384`) |
| hooks per mod | 256 |
| hooks per address (all mods) | 8 pre, 8 post, 1 replace |
| mods loaded | 16 |
| `mod_id` / `mod_name` | 31 / 47 characters plus NUL |

The example's wasm build command (the one fixed by the task) does not pass the memory flags; a production build adds them, or the
loader rejects growable or oversized memory.

## 7. ABI and versioning

| item | rule |
|---|---|
| `gdmod_abi_version` | exported `u32` data object, `(major << 16) + minor`, the ABI the mod was built against. The loader reads it first |
| compatibility | same major required. Host minor at least the mod's `abi_min`. `abi_max` is the highest tested; a host above it loads with a warning |
| additions | a minor adds accessors, view fields (into `reserved`), hook rows, feature bits. A major changes handle encoding, calling convention, view layout or the semantics of an existing row |
| feature flags | `required_features` / `optional_features` (`GD_FEATURE_ITEM_WRITE`, `_ACTION_REQUEST`, `_REPLACE`, `_LOG`). Unknown required bit: refuse. Unknown optional bit: ignore |
| hook table | `hook_table_version` = N of `hooks-vN`. Each declared address must exist in that table |
| `gd_mod_manifest` | exported const `gd_manifest`: magic `GDMD`, `struct_size`, `abi_min`, `abi_max`, `hook_table_version`, `mod_version` (`major<<16 + minor<<8 + patch`), features, `state_bytes`, `hook_count`, `hooks` (array of `gd_hook_decl`), `mod_id`, `mod_name`. Read as plain data before any mod code runs |
| `gd_hook_decl` | `address`, `mode` (1 pre, 2 post, 3 replace), `priority`, `flags` (0), `fn` (native: code pointer; wasm: index in the exported function table) |
| target game | GALE01 1.02 only. Hook addresses are meaningless on another revision |

### Load and refusal rules

| check | on failure |
|---|---|
| valid wasm / native object; wasm imports only module `gd` names of this ABI; no start function; memory fixed within limits | refuse |
| `gdmod_abi_version` major equals the host's; `abi_min` not above the host | refuse |
| manifest magic, `struct_size`, `hook_count` within limit, `mod_id` charset `[a-z0-9._-]`, not already loaded | refuse |
| `required_features` subset of host features | refuse |
| every hook address is in `hooks-vN` for the declared version; mode allowed (`replace` only when `sig_src = decomp`; one replace per address) | refuse |
| `state_bytes` and memory within limits and consistent | refuse |
| `abi_max` below host ABI; unknown optional bits | load, log a warning |

A refusal is never silent and never partial: the whole mod is rejected with a message naming the check and the field, and the host
does not start a match that required that mod. Online and replay sessions carry the mod list (id, version, sha-256 of the module; for
native the build hash) in the session setup; a mismatch between peers refuses to start (OPEN 10).

## 8. Example

```c
#include "gdmod.h"                       /* one TU per mod */
static gd_u32 g_hits;                    /* state: plain global */
static void on_dmg(gd_fighter v, gd_f32 d) {
    if (gd_fighter_slot(v) == 0 && d > 0.0f) { gd_fighter_set_percent(v, gd_fighter_get_percent(v) + 1.0f); g_hits += 1u; }
}
GD_HOOKS_BEGIN GD_HOOK_POST(GD_ADDR_FIGHTER_TAKE_DAMAGE, 0, on_dmg) GD_HOOKS_END
GD_MOD_MANIFEST("gd.hello", "Hello", 0x00010000u, GD_ABI_VERSION, GD_ABI_VERSION, GD_FEATURE_NONE, GD_FEATURE_NONE, sizeof g_hits);
```

Full file: `docs/specs/examples/hello_mod.c`.

| target | command |
|---|---|
| native (compile only) | `clang -std=c11 -O2 -ffp-contract=off -fwrapv -fno-math-errno -ffreestanding -c examples/hello_mod.c` |
| wasm | `clang --target=wasm32 -O2 -ffp-contract=off -nostdlib -Wl,--no-entry -Wl,--export-dynamic -o hello_mod.wasm examples/hello_mod.c` |

## 9. Verification

| # | check | pass criterion |
|---|---|---|
| V1 | loader off vs empty-mod loader: the same `.slp` replay (non-CPU scenario) with the mod loader disabled, and enabled with a mod whose hook list is empty, on the same build | identical NHV1 CSV (`hash` and every part column, every frame) |
| V2 | hook plumbing only: a mod with a pre and a post on every row of `hooks-v1.tsv` that does nothing | identical NHV1 to V1 |
| V3 | the same mod source on both builds: native in the host's build, wasm in ours, the same `.slp` replay | identical NHV1 on every frame (`tools/rust-port/compare_golden.py --common`) |
| V4 | `hello_mod` effect | the first NHV1 divergence from V1 is the first frame with damage to slot 0 in the replay, and V3 holds |
| V5 | rollback: roll back N frames and resimulate (native: restore `.data/.bss`; wasm: restore memory), no save/load code in the mod | digests after resimulation equal the straight run |
| V6 | refusal: bad `abi_min`, unknown required bit, duplicate replace, address not in the table, growable memory | each refused naming the check |

The NHV1 log point is directly after `HSD_GObj_RunProcs()` in `gm_801A4D34` (nhv1.md section 2). Run with the script layer off
(`MELEE_SCRIPTS=0`). Inputs come only from the replay or the scripted pad, never OS input.

## 10. Implementation notes (this repository)

| item | note |
|---|---|
| native Rust port | a hook is installed per `site`: `call` through the `melee_link` seam (`link = yes`) or a new seam; `proc` by wrapping the pointer given to `HSD_GObj_SetupProc`; `state` by wrapping `MotionState` table entries when tables are built; `scene` by wrapping the scene table entry |
| wasm runtime | AOT only; the host provides module `gd`; canonicalise NaN at the boundary; no fuel metering (determinism comes from the code, not a clock) |
| native C build | `GD_ACCESSORS_INLINE=1` with a host header mapping handles to the real struct fields; hooks are direct calls from the same call sites |
