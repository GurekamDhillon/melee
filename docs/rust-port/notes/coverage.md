# Coverage golden set (branch port/coverage)

Goal: C-build hash goldens (NHV1, `MELEE_NEUTRAL_HASHLOG`) beyond the four original scenarios: every character, every VS stage,
items, CPU levels, human-style pad matches, Target Test, Classic/Adventure/All-Star stages. Goldens land in
`docs/rust-port/golden/coverage/<name>.csv` (hash CSVs only). Scenario definitions: `docs/rust-port/golden/coverage/scenarios.json`
(generated by `tools/rust-port/golden/coverage/gen_scenarios.py`; pads by `gen_pads.py`; 1P steps in `onep_steps.json`).

## Shared binary
`E:\Projects\Melee Workspace\_build\agents\coverage-bin\` (read-only by convention): `melee-pc.exe`, `melee-pc.map`, `SDL3.dll`,
`webgpu_dawn.dll`, built from this worktree at the commit in `BUILD_COMMIT.txt` beside them (C sources of the branch family at
191c181f2, i.e. including `cca0989d1`). Recorders never build: they copy it into their own private root.

## Recording
```
export COVERAGE_AGENT=<unique-name>       # private run root _build/agents/<name>
bash tools/rust-port/golden/coverage/record_coverage.sh --batch 3      # or NAME... / --group chars / --all
```
Each scenario runs twice (sandbox `cov-<name>-a|b`), both CSVs must be identical (`compare_golden.py`), then the first is
copied into `docs/rust-port/golden/coverage/`. Existing CSVs are skipped unless `--force` (resumable). A run is about 6-10 s
(3600 frames, turbo); the C build quits itself from the Lua pad at a fixed frame, `--max-seconds` is only a hang guard.
No OS input, no focus: pad scripts (Lua, `tools/rust-port/golden/coverage/pads/`), scene tokens, `MELEE_PAD_IGNORE_ADAPTER=1`,
`MELEE_TURBO=1`, off-screen window. Commit only the CSVs. Seed `MELEE_TEST_SEED` per scenario (default 12345).

## What is covered
- `chars`: 26 CPU9 matches (`char_<name>`, each vs another character, stages rotating over the 6 legal ones), Zelda/Sheik
  transform (`zelda_sheik_transform`, human Down+B twice), Kirby copy (`kirby_copy_a/b`: human Kirby inhaling idle CPUs),
  Ice Climbers human pad, Sheik vs Zelda CPUs.
- `stages`: every retail VS stage, external ids 2..32 (31 scenarios, CPU9 pairs).
- `items`: frequency 4 on five stages, 4-player FFA, human pads, frequency 1, items off.
- `cpulevels`: CPU 1/5/9 on four pairings, mixed levels, 4 CPUs, 2v2 teams, stock matches (game end / results).
- `pads`: six human-vs-human random-segment matches (`rand_sN.lua`) and three human-vs-CPU.
- `targettest`: all 26 characters (`mode=tt;p1=ck:N`), random pad.
- `classic` steps 0..10, `adventure` steps 0..11, `allstar`: `mode=<m>;p1=ck:N;step=S;difficulty=D` boots straight into stage S
  (the mode's own CSS is skipped); the pad plays randomly inside matches and taps A/Start elsewhere to advance cutscenes/results.
  Steps past the last stage clamp to it (classic 10+, adventure 11+), so only the distinct ones are listed.

## Not covered, and why (status "blocked" in scenarios.json)
- Home-Run Contest, Multi-Man (10/100/3-min/15-min/endless/cruel), Event Match: `gw_sl_modes` in `pc/platform/gw_runtime.c`
  has no keyword for GM_HOME_RUN_CONTEST (0x20), GM_10MAN..CRUEL_VS (0x21-0x26) or GM_EVENT (0x2B), and they have no direct
  OnLoad path like Target Test (`MELEE_TARGET_TEST`/`mode=tt`) or the 1P `OnePDirect`. They are reachable only through the retail
  main menu (Special Melee / Event Match). Menu driving needs screenshots to author, and turbo does not present frames, so it was
  not attempted blind. Fix: add scene keywords (and a direct-launch OnLoad, as gmmultiman.c does for Target Test) in the C, rebuild
  `coverage-bin`, add scenarios.
- Trophy lottery/collection/gallery (`mode=trophylottery|trophycollection|trophygallery`): reachable by scene token but run no
  fighters, so NHV1 logs no rows; nothing to record (render-only).
- `mode=tiny|giant|stamina|ssd|slomo|lightning|invisible|camera` with `at=match`: only reaches the CSS (the `at=` states of those
  modes are not wired); dropped.
- Per-character Classic/Adventure/All-Star beyond the rotating sample; Target Test uses one pad per character, so most targets are
  not broken (the run ends when the stage ends: row counts differ per character).

## Rust engine vs the C coverage goldens (2026-11-01, after the covfix rounds)

Wired: VS-mode scenarios with the idle pad script (scene strings with `ck:N`, `ext:N` stage ids, `cpuN`/`human`/`idle`); not wired: 1p modes (adventure/classic/allstar/targettest: the engine boots VS matches only), VS scenarios whose pad is a Lua script (`rand_s*`, `randabs_*`, kirby/zelda_sheik: needs a Lua pad host in the engine), scenes with `stocks=`/`teams=`/team suffixes. Notes on the classes (covfix rounds, 2026-11-01; what was fixed and what is left):
- **fixed: stage archive symbols** (`dat_symbols.tsv`): `_image_desc` -> HSD_ImageDesc (Fountain mirror, Stadium BG), `dynamicsdata_*` -> DynamicsDesc (Castle flags, Rainbow Cruise ship), `ftDataKirbyCopy*` -> KirbyHatStruct, `SIS_*` -> the new `custom:sis` table (words 0/1 typed kerning/textures, the rest raw string pointers; Stadium text `HSD_SisLib_803A660C` read garbage before). `yakumono_param` stays `custom:rawwords` (a regenerated `dat_types.rs` had silently reverted it to raw).
- **fixed: fighters dying at load / first moves** (native-layout differences of GameCube pointer punning in the DAT decode, not game logic): `ftData.x48_items[6]` is an `HSD_Joint*` for Link / Young Link (shield, sword), `[4]` for Kirby, `[3]` for Yoshi, `[10]` an `FtPartsVisLookup[model_num]` for Game & Watch; `TempS.x4` is an index array (`arrays.tsv`), `Fighter_804D6540_t.x0` an array of `x4` rows (Kirby parts), Yoshi's `S_UNK_YOSHI2` is the second `TempS` entry; the fighter article attribute records (Link arrow / boomerang / hookshot, Samus grapple, Ness yo-yo) are picked by their relocated pointer fields instead of an exact block extent.
- **fixed: link casts**: `cast` accepts a scalar -> raw pointer (the C `0` NULL of `ftCo_800DE7C0(gobj, 0, 0)`), `Player_SetHPByIndex` takes an `i32` hp like the C (the call site converted a float). No cast panic showed in the last full run.
- **fixed: stages**: the Battlefield-family BG switch at frame ~3150 (`grBattle_YakumonoParam` pointers widened to raw-image stream addresses), stages with their own `Mex_GrBind` hook (Garden, Yoshi's Island, Onett, Fourside, Flat Zone, Old Kongo, Old Yoshi, figure stages: the generated default returned NULL and `on_init` was called), Onett's one-past `car_jobjs[4]` read, the `Slippi_FrozenStadium` hook (default off, `MELEE_SLIPPI_FROZEN_PS=1`), the `tu_ext` stage-proc hooks (DObj flags, Player_80031790/900, ftLib_80086C18, gm_GetDbPauseFlag / MexVanillaKind / 801674C4), three `ftAction_*` skip handlers, `grAnime_801C752C_fp`, `ft_80081DD4`.
- **fixed: s16 / u8 packed `yakumono_param`** (Stadium, Fourside, Old Pupupu, Old Yoshi): the blind 32-bit word swap exchanged the halves of every s16 pair; `tools/rust-port/engine/gen_yakumono.py` generates per-field widths (`yakumono_layouts.rs`) from the stage TUs' structs. The other stage records with s16 fields also hold pointers (Castle, Corneria, Mute City, Kongo, Ice Mt, Inishie, Venom, Zebes, Big Blue): each still needs a typed decode, and they are the likely cause of several early `hash` divergences above.

Round 2 (covfix, 28 -> 34 of the 79 wired; gate and the 4 goldens green, lint unchanged at 398):
- *Game & Watch article attributes* (crashes in `it_8026EECC`, char_falco / char_gaw / items_hi_dreamland64 / stage_16): word 0 of every G&W special-attribute block is a relocated pointer to an `it_266F_ItemVars` record (`it_8027CE64` stores it in `xDD4`, the item draw reads `x0/x4/x8/xC` through it). The word-swapped 4-byte copy made `*attributes` an 8-byte junk value. `dat_custom::gw_article_attrs` now rebuilds the block as `[native ptr][remaining words, swapped]` (the layout of the native `itGamewatchchefAttributes` ...) and swaps it in with the typed articles.
- *Link-cast class "gobj passed as `&Fighter`"* (26 functions): chara tu bodies for `ftKp_SpecialS_80132DC0..E20` (Bowser capture getters), the G&W `*_ItemCheck*Remove`, `ftPe_SpecialN_IsActive`, `ftSk_SpecialS_80110F58/64`, `ftYs_SpecialN_GetDatAttr*/GetFacingDir/SetupItemVel`, `ftKb_SpecialNGw_8010D160` took `&Fighter` where the C takes the fighter gobj; the link `cast` transmuted the gobj pointer, so they read garbage (cpu_ffa4_levels crash at 110 -> 120, G&W item removal). They now take `*mut HSD_GObj` like the C. Check: `python tools/rust-port/golden/coverage/scan_gobj_refs.py` (a regex over the `gen_table.rs` hooks against the C definition's parameter types; prints 0 now).
