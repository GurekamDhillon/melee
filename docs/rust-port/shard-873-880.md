# Menu shard 873-880: mnnamenew, mnruleplus, mnsnap, mnsound, mnsoundtest, mnstagesel, mnstagesw, mnvibration

All eight TUs are in `melee_modes` (inventory section 4) as `rust/melee_modes/src/tu/<stem>.rs`, one
`pub mod` line each in `tu/mod.rs`. None is dead on PC.

Method: the c2rust output (`src/raw/melee/mn/`) was cleaned mechanically (C types to Rust ints, string
literals to `c"..."`, literal casts, asserts to `__assert`, varargs to slices, pad locals dropped), then
fixed by hand: every contracted float multiply-add is `melee_core::fp::fmadds` (mnsound getVolumePosition,
mnstagesw cursor/text rows, mnvibration cursor rows, mnsnap thumbnail rows, mnstagesel cursor drift);
function-local C structs are named Rust structs with `gc_layout!` offsets; header records (MenuFlow,
MenuInputState, MenuRulesPlusData, stagelistinfo, MenuInput_*) come from the one generator
(`melee_types/gen/gen_types.py`, three headers added to the probe).

Shared pieces: `src/mn_inl.rs` (menu globals owned by unported mnmain.c, the mn/inlines.h and jobj.h
inlines, the variadic callees as slice-taking stubs: `lb_80011E24`, `lbArchive_LoadSections`,
`HSD_SisLib_803A6B98`, `HSD_ForeachAnim`).

Callees in unported TUs are `ext_fns!` stubs named like the C function (TODO panic unless a test hook is
installed); callees ported elsewhere (`gm_1601`, `gmmain_lib`, `gm`, `gmfrontend::Frontend_CaptureIcon`,
`mnstagesw`/`mnruleplus` cross calls) default to the port.

Not done (task rules: no test runs, no oracles): no C oracle exists for these TUs, so nothing here is
verified bit for bit. Review focus when an oracle is written: the `current_block` state machines c2rust
left in the long input handlers, float->int casts (Rust saturates to the target width, gwtool saturates to
i32 then truncates), and the GC-vs-native struct sizes (`gc_layout!` carries the GC offsets only).
