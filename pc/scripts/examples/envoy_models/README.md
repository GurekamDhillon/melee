# envoy_models (original item, room and frame models for Envoy)

The second Envoy model set, made the way the Party drive models are (`../envoy_drives`): **every mesh, texel and
sprite here is original to this project and generated by `tools/make_models1.py`**. Nothing is traced, converted or
taken from a game, a model file or another project. An asset-only mod (`kind: misc`): no script.

`python tools/make_models1.py` rewrites everything (`tools/models2.py` holds the second chunk's part lists); `--check` proves the files on disk are what the script makes;
`--sheet OUT.png` also draws the contact sheet. The meshes, atlas and manifest need only the standard library; the
sprites need numpy and Pillow. The generator imports `../envoy_drives/tools/drive_parts.py` for the primitives
(bevelled prism, ring, ball) and the colour ramp, so the two sets cannot drift apart.

| file | what |
|---|---|
| `models/em_<key>.gxmesh` | GXMS v2, the drives' format and frame: the parts box (-1..1) times 2.2, not recentred |
| `models/envoy_models_atlas.gxtex`, `.glow.gxtex` | 128 x 256 colour ramps + glow (GXTX v1 RGBA8), rows of 4 texels (append, never reorder) |
| `models/envoy_models.txt` | the manifest: one key per line, in model order (a key's line is its model id: append, never reorder) |
| `models/envoy_models.inc.rs` | the same list as the host's `include_bytes!` array (`rust/melee_modes/src/tu/drive_draw.rs`, `EM_FILES`) |
| `models/em_<key>.coll.json`, `.material.json` | no collision; `lit` + emission (as the drives) |
| `rust/mods/envoy_ui/art/em_<key>.png` | the same model as a 96 x 96 sticker sprite (48 game pixels at 2x), ink edge |

The list of models, what each one means and where it belongs is `docs/rust-port/notes/envoy-models1.md`.

A pool frame (`em_frame_*`) is drawn behind an item at the same centre. As meshes the two share one frame, so the
same position, yaw and scale line them up. As sprites the frame shows 4/3 as much of the box: draw it at 4/3 the
item's size (item 48, frame 64).
